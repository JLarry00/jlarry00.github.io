# Plan, update, and close a delivery cycle

## Plan

- Read the product backlog and the most recent closed cycle.
- State one reviewable goal and select only the work needed for that goal.
- Keep the original scope visible. Do not add points, capacity, or dates unless the user supplied them and the product records explain their source.
- Define acceptance checks that can be observed. Identify decisions or evidence that remain with Juan.

## Update

- Change statuses only when there is evidence in the code, documents, or user decision.
- Record additions or removals from the selected scope with date, reason, and effect on the goal.
- Put unrelated discoveries into the product backlog.
- Record a blocker with the specific dependency and next action. Do not invent a person to own it.

## Close

- Compare each selected item with its acceptance condition.
- Separate implementation, local verification, remote workflow result, and publication state.
- Move incomplete work back to the same product backlog and retain the reason.
- Write a closed sprint record under that product's sprints/ directory; update SPRINT_ACTUAL.md, BACKLOG.md, and VERSIONES.md together.
- Do not rewrite the closed record later to make the outcome look cleaner. Add a dated correction if a material fact changes.
